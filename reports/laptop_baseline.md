# Отчёт: baseline на ноутбуке (ResNet18 + линейный классификатор)

Ветка `experiment/laptop-baseline`. Агрегированные числа: `reports/laptop_baseline_metrics.json`.
Подробные предсказания, разбиения, признаки и веса лежат вне Git (`data/`, `models/`).

## Что сделано

Замороженный ResNet18 (torchvision, `ResNet18_Weights.IMAGENET1K_V1`) даёт 512-мерный признак кадра;
поверх него обучен линейный бинарный классификатор (стандартизация + логит). Задача — только наличие
события и его время; типы нарушений и нормативные пункты не оцениваются. `DummyPipeline` в API не заменён.

- Кадры: последовательное чтение OpenCV, ≈2 fps, временные метки декодера; преобразования весов (resize 256, center crop 224, нормализация ImageNet); batch 16, `num_workers=0`.
- Положительные обучающие кадры: ±1 с вокруг размеченного таймкода (приближённая разметка); отрицательные — все кадры видео без нарушения. Вес каждого видео равный, затем классы уравновешены.
- Оценка видео: максимум вероятности по **всем** кадрам; таймкод — время максимума; истинный таймкод при анализе не используется.
- Выбор по validation: weight decay (0 / 1e-3 / 1e-2 / 1e-1 → 1e-2), число эпох (ранняя остановка, patience 5, лучшая эпоха 3), порог **0,648** (максимум F1; при равенстве — больший recall; далее больший порог).
- Нормализация признаков считана только на train.

## Окружение

Windows 11, NVIDIA GeForce RTX 5060 Laptop GPU (7,96 ГиБ VRAM, compute capability 12.0), драйвер 591.91, Intel i5-13450HX (16 потоков), 15,6 ГиБ RAM. Python 3.11.9, torch 2.14.1+cu130, torchvision 0.29.1+cu130. Проверка CUDA forward/backward пройдена; вычисления выполнены на GPU.

## Данные

42 строки в `labels.csv`, 40 уникальных содержимых. Исходные файлы и метки не менялись.

- Группа `Х-4` / `Х-47` — одно и то же видео с таймкодами 57 и 68 с: **исключена целиком** (2 файла), в списке для уточнения разметки (`data/splits/laptop_baseline/excluded.csv`).
- `Х-5` / `Х-48` — точный дубль с одинаковой меткой: один представитель, соответствие сохранено.
- Итого 39 уникальных видео, seed 42, разбиение по группам со стратификацией по классу:

| Выборка | Видео | С нарушением | Без |
|---|---|---|---|
| train | 23 | 12 | 11 |
| validation | 8 | 4 | 4 |
| test | 8 | 4 | 4 |

(≈59% / 21% / 21%: ближайшее разбиение при 39 группах.) Пересечений групп нет (проверяется тестами).

## Результаты на test (8 новых видео, порог зафиксирован на validation)

| Вариант | TP | FP | FN | TN | Recall | Precision | F1 |
|---|---|---|---|---|---|---|---|
| **Модель** | 3 | 4 | 1 | 0 | 0,75 | 0,43 | 0,55 |
| Всегда «нарушение» | 4 | 4 | 0 | 0 | 1,00 | 0,50 | 0,67 |
| Никогда «нарушение» | 0 | 0 | 4 | 4 | 0,00 | 0,00 | 0,00 |

Средняя абсолютная ошибка таймкода на 3 верно найденных видео: **10,2 с**. Пропущено 1 нарушение. Ошибок обработки нет.

Для справки (не результат на новых видео): validation (использована для выбора настроек) — TP 4, FP 2, FN 0, TN 2, F1 0,80, ошибка таймкода 9,9 с; train (обучающие видео, пересчёт) — TP 12, FP 6, FN 0, TN 5, F1 0,80, ошибка 2,9 с.

**Вывод:** на test модель не лучше тривиального «всегда нарушение» и не отличает отрицательные видео (TN = 0). Baseline не показал рабочего качества.

| Анализ test-видео, 1-й проход: среднее / максимум | 0,84 / 1,83 с |

Весь эксперимент уложился в бюджет (минуты вместо 60). Видео короткие (в сумме 24 мин); «холодный» проход выполнен в одном процессе с уже загруженной моделью и файловым кэшем ОС, поэтому от тёплого почти не отличается.

## Повторяемость

`scripts/verify_laptop_model.py`: два новых процесса загружают модель только из локальных файлов (сетевые соединения запрещены в процессе), заново анализируют 3 test-видео; расхождение оценок 0,0 между процессами и с сохранёнными предсказаниями, решения и таймкоды совпали. Оценки двух проходов оценки также идентичны. Тесты сервиса и новые тесты: 22 теста, OK.

## Ограничения

- Очень малый test (8 видео, по 4 класса): одна ошибка меняет метрики на 12,5 п.п.; результат нестабилен.
- Кадровые метки приблизительны (±1 с); остальные кадры положительных видео не использовались.
- Классификатор мог выучить фон/ракурс/сцену отдельных видео, а не действие; признаки отдельных кадров не учитывают временной контекст.
- Почти все видео получили высокий максимум оценки — пик по всему видео шумный (ложные срабатывания).
- Не оценены типы нарушений и нормативные пункты — в разметке их нет.
- Первая установка PyTorch прервалась из-за несовпадения хэша при скачивании, повторена без кэша; на результат не влияет.
- Статистика извлечения признаков за train+val частично берёт 4 видео из кэша, созданного пробным запуском.

## Воспроизведение

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-ml.txt
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe scripts\prepare_laptop_data.py
.\.venv\Scripts\python.exe scripts\train_laptop.py --smoke      # короткий пробный запуск
.\.venv\Scripts\python.exe scripts\train_laptop.py
.\.venv\Scripts\python.exe scripts\eval_laptop.py
.\.venv\Scripts\python.exe scripts\verify_laptop_model.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Требуются `data/videos/`, `data/labels.csv`, `data/dataset_check.json`. Первый запуск обучения один раз скачивает веса ResNet18 из torchvision; дальше модель работает из `models/laptop_baseline/` без сети.
