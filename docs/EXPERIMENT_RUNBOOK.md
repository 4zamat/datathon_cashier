# Следующий запуск, сохранение ноутбука и Brev

## 1. Что забрать с ноутбука сейчас

Нужны **результаты обучения**, которых нет в Git: `models/laptop_baseline/{encoder_resnet18.pt,head.npz,config.json}`, содержимое `data/splits/laptop_baseline/`, `data/runs/laptop_baseline/`. Исходные видео у нас уже есть. `.venv` и большой кэш признаков не нужны для применения сохранённой модели.

Сначала сохранить незакоммиченную работу подруги в её ветке. Затем, из клонированного проекта:

```powershell
git status --short
git fetch origin
git switch -c handoff/laptop-results origin/fix/experiment-rules-handoff
python scripts/export_experiment.py --output data/exports/laptop-results-original.zip
python scripts/export_experiment.py --verify data/exports/laptop-results-original.zip
```

Использовать её Python 3.11 или `.\.venv\Scripts\python.exe` вместо `python`. Экспортёр использует только стандартную библиотеку: работает даже без CUDA/Torch. Переключение ветки не меняет игнорируемые веса и видео. Если Git отказал из-за локальных изменений, сохранить их в своей ветке; не применять принудительный checkout. Уже существующую ветку открыть через `git switch handoff/laptop-results`.

Экспортёр собирает только разрешённые файлы: веса, config, train/val/test/excluded/summary, train_log, два набора предсказаний, reload_check, доступные метрики, снимок исходников и версии установленных пакетов. `manifest.json` содержит SHA-256 каждого файла. Снимок кода относится к моменту экспорта; для первого опыта точный код обучения не доказан одним старым `code_commit`, и это явно отмечено.

**Сдать:** ZIP + напечатанный SHA-256 + ссылку на свой commit, если были изменения. Ожидаемый размер в основном определяется энкодером около 45 МБ до сжатия, а не 300 МБ видео. Архив передать приватно согласованным способом; веса и перефайловые результаты не коммитить. Если есть исправленные разметки или исходники вне репозитория, передать отдельно с пояснением.

`complete: true` означает наличие ожидаемых файлов и совпадение хэшей, **не успешное обучение или проверку модели**. Нужно отдельно прочитать `reload_check.json` (`passed: true`) и отчёт об ошибках обработки. При нехватке файла архив всё равно сохраняется с `complete: false`, список `missing_required`, код выхода 2: передать этот частичный архив тоже, затем дослать отсутствующее, если оно есть. Никакой архив не перезаписывается.

На нашем компьютере выполнить `--verify` с полученным архивом. Распаковать в **новую** папку `data/imports/laptop-original/`: внутри `model/`, `run/`, `splits/`, `source/`, `historical_reports/`. Для проверки предсказаний передать эти каталоги в `verify_laptop_model.py`, используя исходные видео из `data/videos/`. Сначала нужны ML-зависимости и совместимое устройство. Проверка ZIP сама не требует GPU.

Если ноутбук исчезнет без этого архива, код и видео позволят обучить заново. Восстановить именно её веса, порог и перефайловые результаты из одного агрегированного отчёта нельзя.

## 2. Запуск на том, что уже есть

Это **диагностический бинарный baseline v2**, не готовый распознаватель отдельных банковских нарушений. Он проверит исправления и даст точку сравнения. Используются те же видео и имена. Ничего не надо перекодировать или повторно отправлять 300 МБ, если данные уже на машине.

Работать на базе `origin/fix/experiment-rules-handoff`, в своей ветке. Команды ниже используют `python` активированного окружения Python 3.11; на Windows можно заменить на `.\.venv\Scripts\python.exe`. Проверить:

```bash
python --version
python -m pip install -r requirements-ml.txt
python -c "import torch; print(torch.__version__, torch.version.cuda); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0)); x=torch.ones(2,device='cuda',requires_grad=True); (x*x).sum().backward(); print(x.grad)"
python -m unittest discover -s tests -v
```

Не переустанавливать рабочие зависимости на ноутбуке до резервного экспорта. `requirements-ml.txt` фиксирует окружение первого опыта; для другого GPU/драйвера сначала подтвердить поддержку этой сборки. При недоступной CUDA команда проверки должна завершиться ошибкой, а не скрытно перейти на CPU.

В `data/` должны быть `labels.csv`, `dataset_check.json`, исходные `videos/`. Эти небольшие метаданные уже передавались отдельно от видео. Подготовка сверяет реальные SHA-256 с проверкой датасета; при расхождении остановиться и выяснить причину.

```bash
python scripts/prepare_laptop_data.py --out-dir data/splits/laptop_v2_provisional
python scripts/train_laptop.py --split-dir data/splits/laptop_v2_provisional --out-dir data/runs/laptop_v2_provisional --model-dir models/laptop_v2_provisional --device cuda --smoke
python scripts/train_laptop.py --split-dir data/splits/laptop_v2_provisional --out-dir data/runs/laptop_v2_full --model-dir models/laptop_v2_provisional --device cuda --epochs 20
python scripts/eval_laptop.py --split-dir data/splits/laptop_v2_provisional --model-dir models/laptop_v2_provisional --out-dir data/runs/laptop_v2_full --device cuda
python scripts/verify_laptop_model.py --split-dir data/splits/laptop_v2_provisional --model-dir models/laptop_v2_provisional --run-dir data/runs/laptop_v2_full --device cuda --videos 3
python scripts/export_experiment.py --split-dir data/splits/laptop_v2_provisional --model-dir models/laptop_v2_provisional --run-dir data/runs/laptop_v2_full --output data/exports/laptop-v2-provisional.zip
```

Smoke сохраняется отдельно внутри первого `--out-dir/smoke`. Полный запуск использует другой каталог результатов. Уже заполненные каталоги обучения/разбиения и существующие файлы оценки не перезаписываются. Для повтора выбрать новый ID в путях. Не удалять результаты первого опыта для удобства нового запуска.

Во время первого обучения torchvision может скачать ImageNet-веса. Для полностью офлайн-обучения добавить к обеим train-командам `--encoder-weights models/laptop_baseline/encoder_resnet18.pt` (или путь к энкодеру из полученного архива). `HF_HUB_OFFLINE=1` не отключает загрузки torchvision; локальный файл здесь необходим. Инференс `load_model` читает только локальные веса.

Изменения v2: FP32-кэш без потери точности между запусками, отдельная версия кэша, полная взвешенная оптимизация линейной головы, хэши источников/разбиения/модели, проверка неизменности видео, сверка сохранённого таймкода, ненулевой код при ошибках оценки. Это меняет процедуру обучения: старые метрики нельзя выдавать за результат v2.

Без ручного `scene_groups.csv` известны только точные дубли. Х-4/Х-47 исключаются, Х-5/Х-48 объединяются: ожидается **39 уникальных используемых видео, 23/8/8**. Это временная оценка. Она не доказывает отсутствие утечки через похожие сцены и не является новым независимым test: прежний результат этих восьми роликов команда уже видела. Не подбирать по ним порог или новые настройки; для честного финального вывода нужны независимые сцены/данные.

Достаточно одного такого запуска. Если опять все отрицательные видео дают тревогу, не перебирать десятки настроек на том же test. Перейти к согласованной разметке конкретных событий и временной модели. Нулевая ошибка времени на нескольких TP тоже не компенсирует пропуски и ложные тревоги.

## 3. Когда закончена ручная разметка

```bash
python scripts/validate_annotations.py --events data/annotations/v1/events.csv
python scripts/prepare_laptop_data.py --scene-groups data/annotations/v1/scene_groups.csv --out-dir data/splits/reviewed_scenes_v1
```

Групповой CSV должен покрывать все исходные видео. `uncertain` и `exclude` исключают записи; одинаковые файлы требуют общего ID группы. Похожие фрагменты с разными классами могут иметь общий ID — они целиком попадут в одну часть. Алгоритм ищет приблизительный баланс; если независимых групп недостаточно, останавливается с ошибкой.

Эта команда **не заменяет исходные метки наблюдениями из events.csv**. Интегратор отдельно фиксирует согласованные исправления в новом CSV, например `data/labels_reviewed_v1.csv`, и передаёт `--labels data/labels_reviewed_v1.csv`. Для нескольких событий нужна событийная разметка, а не потеря всех таймкодов кроме одного. Типы/интервалы для следующей модели читает её отдельный event-trainer.

Обучающий код читает кадры только train/val; test CSV используется для проверки непересечения и хэша версии. Порог выбирается по validation. Не делить кадры одного ролика между частями.

## 4. Brev: запасная машина, когда ноутбук недоступен

**Да, Brev подходит как место запуска нашего обучения. Сейчас аренда не нужна, если ноутбук доступен:** первый опыт занимал минуты и мало VRAM. Переход нужен при потере доступа к ноутбуку или измеренной нехватке ресурсов следующей модели. Это аренда GPU-машины для нашего кода, не обязательное использование облачного API распознавания.

Перед передачей банковских видео на внешнюю инфраструктуру уточнить у организаторов допустимость такого хранения/обработки: запрет внешних AI API сам по себе не отвечает на вопрос о загрузке датасета на арендованный сервер. В этой работе VM не арендуется и данные никуда не загружаются.

1. После решения об аренде выбрать одну подходящую GPU-машину, проверить цену и лимит расходов в консоли. Для нынешнего baseline ориентир — уже работавшие 8 ГиБ VRAM и 16 ГиБ RAM; покупать H100 ради него оснований нет. Для новой модели сначала измерить потребление smoke-запуском.
2. Подключиться по SSH, хранить проект в `/home/ubuntu/workspace/`, клонировать нужную ветку. Убедиться в Python 3.11 и совместимости драйвера с PyTorch из requirements; предустановленный Python не обязательно 3.11.
3. Передать через согласованный приватный канал исходные `data/videos/` и маленький пакет метаданных, либо восстановить ранее загруженную копию. На новую машину видео понадобятся один раз; между опытами повторно их передавать не нужно. Архив весов позволит применить старую модель без переобучения.
4. В Linux создать окружение и выполнить те же команды из раздела 2:

```bash
cd /home/ubuntu/workspace
git clone --branch fix/experiment-rules-handoff https://github.com/4zamat/datathon_cashier.git
cd datathon_cashier
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-ml.txt
nvidia-smi
```

Далее — CUDA forward/backward-проверка, тесты, подготовка, smoke, полный запуск, оценка и экспорт. Если Python 3.11 или драйвер неподходящие, сначала выбрать/настроить окружение, а не менять версии наугад. Dockerfile сервиса пока описывает CPU Dummy; считать его готовым ML-образом с CUDA 13 нельзя.

5. До отключения VM скачать и проверить приватный архив, отправить код в свою ветку, записать команды и стоимость. **Stop сохраняет рабочий диск, но за хранение остаётся плата; повторный старт зависит от наличия GPU. Delete удаляет данные.** Не полагаться на остановленную VM как на единственную копию весов.

Источник по жизненному циклу и хранению: [официальная документация NVIDIA Brev](https://docs.nvidia.com/brev/concepts/gpu-instances). Тарифы и доступность проверять в консоли в момент выбора машины.
